# Soloverk – Map of the App

Soloverk is a Next.js App Router app: pages in `app/` read from Neon through Prisma, `actions/` change the data, and Clerk and Stripe handle login and payment.

## How a request flows

Example: you open the invoice list with a filter and a sort, `/dashboard/invoices?status=SENT&sort=due&dir=asc`.

1. The browser asks for that URL.
2. `app/dashboard/invoices/page.tsx` runs on the server and reads the URL parameters.
3. The page calls Clerk's `auth()` to get your `userId`; without it, it stops.
4. It asks Prisma (`lib/prisma.ts`) for only your invoices in Neon, filtered and ordered.
5. `lib/invoice-calculations.ts` works out each invoice total.
6. The page returns HTML. Labels come from `messages/nb.json` or `en.json` through next-intl.
7. Changes (save, duplicate, mark paid) go through a server action in `actions/`, then the page shows the new data.

The same pattern repeats everywhere: URL, server page, Prisma, HTML. Only the page and the data change.

## Server actions and the Stripe webhook

A server action is a function that runs only on the server and is called from a button or form. Everything that writes data lives in `actions/`.

| File | What it does |
| --- | --- |
| `actions/invoice.actions.ts` | Creates, updates and deletes invoices, changes status. Checks input with `lib/zod/invoice.schema.ts`. |
| `actions/company.actions.ts` | Saves your company profile. Checks input with `lib/zod/company.schema.ts`. |
| `actions/subscription.actions.ts` | `createCheckoutSession` opens Stripe checkout (with the 25% MVA tax rate). `createPortalSession` opens the Stripe billing portal. |
| `actions/locale.actions.ts` | Saves the NO/EN choice in a cookie and refreshes the page. |
| `app/api/webhooks/stripe/route.ts` | Stripe calls this after checkout, renewal or cancellation. It verifies the signature, then writes your plan status to the `Subscription` table. |

Why the webhook matters: Pro is unlocked by what Stripe tells this route, not by the success page. If the webhook fails, a paying customer stays on Free.

## Logic, data and translations

| File | What it does |
| --- | --- |
| `lib/prisma.ts` | One shared database connection. Every page and action imports it. |
| `lib/invoice-calculations.ts` | Totals and MVA for an invoice. The invoice list, PDF and reports all use it. |
| `lib/invoice-reports.ts` | Groups invoices into the numbers for the reports page. |
| `lib/subscription.ts` | Answers "is this user on Pro?" (reads the `Subscription` table). |
| `lib/stripe.ts` | The Stripe client, created from `STRIPE_SECRET_KEY`. |
| `lib/legal-info.ts` | Company name, org.nr and contact email for the footer and legal pages. Change them here once. |
| `lib/pdf-i18n.ts`, `lib/pdf-theme.ts` | Text and colours for PDFs. |
| `lib/zod/*.schema.ts` | Rules for what the forms may send (required fields, formats). |
| `i18n/request.ts` | Picks the language from the cookie and loads the matching file. |
| `messages/nb.json`, `messages/en.json` | Every visible text, in Norwegian and English. A new label needs a key in both. |
| `prisma/schema.prisma` | The database tables: `CompanyProfile`, `Invoice`, `Subscription`, `WorkLogItem`. |
| `prisma/migrations/*` | History of database changes. Run `prisma migrate deploy` against production after a schema change. |
| `prisma/reset.ts` | A reset script. Check what it deletes before you ever run it, and never against production. |
